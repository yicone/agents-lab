# Agent Atlas 路线图

方向与先后以本文为准；执行状态只看 Multica，不在本文重复。依据：ACM-383 中用户 10-24 确认的规则、现有设计与契约、已合入的 ACM-377 设计系统（`docs/design-system.md`）、issue 原文及相关评论；跨 harness 方向同时依据 ACM-415 / ACM-418 的盘点、ACM-420 汇总结论及用户更正。

## 使用规则

- 各板块按「现在 / 下一步 / 以后 / 不做」组织；它们是方向优先级，不是 issue 状态。「现在」包含本轮需要收拢验收或交付的目标，不表示重新实施历史交付。
- 「现在」「下一步」每条至少关联一个 issue；历史 issue 只作来源时明确标注。「以后」允许未开单；进入「下一步」才开对应执行单，不提前堆积 backlog。
- 交付中推迟的事项先加入「以后」，不能只留评论。本文不授予推送、合并、部署或任何真实写操作权限；push、PR、合并、部署须用户点名 issue、动作与 SHA 逐项批准。
- 新页面按设计系统定位数据层、选版式、复用组件。验收需与 Skills 同宽截图对照（1440px、1100px），补深色及 390px、键盘操作；未知、未采集、失败不能画成零或正常。
- 本机、仓库、Multica workspace、agent 四层各自保留身份与证据，不把同名资源、可见性、安装分配、实际加载混为一谈。

## Agents（含 bots）

### 现在
- **全景只读与指令补采**：保留 Multica Agents、Grok Bots、Instructions / Skills 抽屉和 Git 真源对照；其余九个 workspace 的指令由用户本人在授权终端补采，任务令牌不绕过 workspace 边界。[ACM-290](mention://issue/01a15798-3e52-732b-8089-3ab66fdb80bf)、[ACM-332](mention://issue/01a16327-c7de-77af-a4ca-83ac73157af2)
- **模型与 Runtime 切换写入（首个写入热点）**：在统一写入安全底座上直接实现单 agent 切换；支持模型、推理、Tier 和明确选择的批量切换，逐项预览、确认、写入、读回、回滚和审计。配置写入与实际生效分开显示；不自动切账号或 runtime，不修改秘密字段。用户已确认进入实现。[ACM-450]
- **G1 计划与切换流程**：选择、预检、逐行差异、确认和执行结果；一份计划一个 workspace，`null` 与空字符串保留区别，hash 不是批准。[ACM-231](mention://issue/01a14abd-4777-7469-bb77-fd10f4ccf511)、[ACM-279](mention://issue/01a15244-c6a6-7674-bdb4-9935a7eb0217)

### 下一步
- **G1 边界补强**：处理矛盾分页快照校验、离线启动鉴权超时、同值字段展示三项；先核对已有修复，避免重复实施。[ACM-330](mention://issue/01a16307-27ba-7db4-8e5b-33d79deed931)

### 以后
- **G2 批量切换执行与条件回滚**（未开单；来源 ACM-231）：依赖跨板块统一写入安全设计及平台能力证明，不把 G1 或设计评审通过当成 apply 授权。
- **Instructions / Skills 同步**（未开单；来源 [ACM-294](mention://issue/01a15854-d965-7efc-960d-dfa151b2dde7)）：Git 真源、diff / dry-run、受控写回与回读统一纳入写入安全线；已有 CLI 能力不等于页面写入口获准。
- **创建 / 复制 / 修改 agent**（未开单；用户在聊天中确认，已记录 ACM-383）：逐条预览和确认。复制不复制 `custom_env`、`mcp_config`、`runtime_config`，必须提示并支持一键补齐；补齐同样走独立授权，不回显秘密值。
- **Grok Bot 证据补齐**（未开单；来源 ACM-290 / ACM-349）：区分直接实测与共享机制推断，未来 memory、sessions、hooks 等依赖先研究公开或本机只读来源，再定范围。

### 不做
- 不逆向调用 Grok Bot 私有写 RPC；不把共享 skill 名称清单当成逐 Bot 的绑定或加载证明；不因配额信号自动切账号或 runtime。

## Skills

里程碑：**Skills v2（治理二期）**包含登记与展示口径、实时重叠检测、只读上游版本检查、runtime 加载证据；SkilLock 接入另有前置。**升级审批**单列后续里程碑，不能混进只读 v2。

### 现在
- **清单口径与登记机制**：统一 Multica Workspace / Grok Bot 来源、内容哈希对账、符号图例和技能根证据；登记机制只自动补基础事实，不自动填写复核结论，定时触发另行批准。[ACM-349](mention://issue/01a164b5-164f-7643-a7ff-a86b744c9eda)、[ACM-350](mention://issue/01a164b5-1b2f-7040-a874-7aea8485ff52)
- **只读升级检查**：按来源查询 npm registry / GitHub API，缓存和限频；网络失败或不可比较明确显示缺口，不说「无更新」。[ACM-358](mention://issue/01a164e3-a4c9-7ddd-b826-3114e6f2772c)

### 下一步
- **实时重叠检测**：接入 `conflict_report`，实时结果与人工标记分开显示，新增 skill 也被覆盖。[ACM-357](mention://issue/01a164e3-9e11-709e-ab61-d6cd313374ec)
- **加载证据**：Codex / Cursor / Hermes 先行，分别记录只读证据与可信度；拿不到就保持未验证，不从磁盘可见推断已加载。[ACM-360](mention://issue/01a164e3-aed0-7f18-87e7-80d4d1070658)
- **SkilLock 扫描覆盖处置**：先处理上游草稿与本地投影附件漏测的需求边界；不改 PATH、不重启看板、不提交 `skills.lock`，不把空扫描或部分测量当成门禁通过。[ACM-359](mention://issue/01a164e3-aa68-717e-8f78-190e3c21aa88)

### 以后
- **Skill 可编辑登记**（未开单；来源 [ACM-309](mention://issue/01a15a32-00ca-725a-93e1-25bd2fe8b223)）：先设计本地 / Workspace / 第三方的可写边界、保存目标和冲突处理，依赖统一写入安全设计。
- **任意两个 Skill 内容比较**（未开单；来源 ACM-309）：用户选两个版本或入口看正文差异；不能用跨层漂移摘要替代正文比较。
- **Skills 升级审批进入 Atlas**（未开单；来源 [ACM-181](mention://issue/01a143ce-9544-73a1-8071-e3fbf0977801)，用户在聊天中确认，已记录 ACM-383）：保留批准 / 拒绝方向，依赖统一写入安全设计、暂存与 diff、完整扫描覆盖和审计；并非取消或永久排除。
- **SkilLock 真正接入看板**（后续执行单未开；来源 ACM-359）：先修本地投影附件漏测，再评估上游入口链接支持；上游草稿不是本地修复替代品。
- **Workspace Skill 正文采集与证据补齐**（未开单；来源 ACM-309 / ACM-336）：保留权限与读取失败边界，不以「正文未采集」冒充空正文；上线端到端证据另验。

### 不做
- 不自动批准能力变化、不自动填复核时间与定制约束、不把 SkilLock 当沙箱；不恢复搁置的多仓库视图。

里程碑：**MCP v1 重做**是扩大只读采集并对齐 Skills；**MCP v2**才讨论受控写入。重做不是写入版。

### 下一步
- **MCP v1 重做**：遵循已合入的 ACM-377 设计系统；采集本机各 harness 全局配置、agents-lab 项目配置、workspace 库和 agent 分配，按来源卡片、单表分组、工具列和单一详情抽屉对齐 Skills。同名配置只比指纹，不显示配置取值、env、header、token。[ACM-378](mention://issue/01a16937-2128-7e42-bc9f-116674a36295)

### 以后

### 不做

## 运行指标与额度

里程碑：**运行指标 v1（只读）**——把 run、失败、返工和额度健康度统一成一份只读结果，Atlas 与巡检共用同一口径，调度只依据「当下额度健康」，不依据历史失败。依据：ACM-525（S1–S8）；S4 回放结论用户已于 10-26 通过。

### 现在
- **Atlas 只读运行指标视图（S5）**：接入统一结果 `run-metrics.v0.1`，不增加写入口；失败分类显示规则 ID 与证据，规则外为 unknown；成功率同时给含 / 不含 cancelled 两种及各自分母；返工只报下限，不宣称点估计；runtime 在线数按实际读取显示，不照抄历史口径。[ACM-571]
- **巡检消费统一结果（S6）**：流速巡检与 multica-patrol 读同一份结果，不另立口径；统一结果文件落地与真实数据被消费须单独观察验证，不以代码合入代替。[ACM-572]
- **额度采集稳健性**：usage-collector 保留 CodexBar 的真实错误并过滤升级提示；代理变量只放一处的口径待定。[ACM-642]

### 下一步
- **影子试运行（S7）**：只记录建议路由，不改实际派单；通过阈值按 S4 回放数据提案后由用户确认，不预先定。[ACM-573]
- **小范围启用（S8）**：启用范围、目标 SHA 与回退方法先写在 ACM-525 顶层评论，用户确认后才动手，保留回退。[ACM-574]
- **分池额度预警**：按额度池分级提示，陈旧样本显示未知；实时额度信号 unknown 时允许低风险探测，不作硬禁用。[ACM-414]、[ACM-586]

### 以后
- **失败规则 v0.2**（未开单；来源 S4 抽样）：补 geo / access 限制、broken pipe / EPIPE、runtime recovery、配置或模型不可用、HTTP 503 包装 quota 的识别；需另行审定，不自动落地。
- **provider_unstable 阈值**（未开单；来源 S4 提案）：同 runtime、同签名，滚动 24 小时至少 3 条，排除 quota / capacity / access_denied；用户批准前原型不得产出该类，只给候选与样本数。
- **结构化返工字段**（未开单）：`rework_of_run_id`、`rework_trigger_event_id`、`rework_reason`；仅当返工链覆盖率长期不足才申请，需单独批准。

### 不做
- 不把历史额度失败当永久不可用；不从错误文案猜分类；不因配额信号自动切账号或 runtime；S8 明确启用前不改实际派单逻辑。

## Agent 配置与能力页

信息架构；口径均为用户 10-27 前后已拍板，能力页与 Memory 的口径按用户 10-28 改判。依据：ACM-607（术语与 IA）、ACM-613（skill 正文只读来源）、ACM-496（IA 评审）、ACM-576 / ACM-577（Memory 来源调研）。

里程碑：**Agent 配置与能力页 v1（只读 IA 落地）**——按本节「现在」的口径落地只读信息架构，不含写入。前提：hooks 数据来源待核实（另有调研单）。
- 执行单：术语 [ACM-660]；运行配置字段组 [ACM-661]；能力页三类并列与来源筛选 [ACM-662]；Memory 标签页 [ACM-663]（数据来源核实后才做）；能力三态 [ACM-664]。
- 验收标准：
  1. 全站不再出现「跑法」；跨工具术语只出现在 Agent 配置页和能力页；顶栏不变。
  2. 运行配置字段组与职责块分区显示。
  3. 能力页 skills、MCP、hooks 三类并列，不含 Memory。
  4. Declared / Reachable / Observed 三态均有真实条目，或明确显示 missing。
  5. 全程只读，不显示 env、header、token。
  6. 每个 PR 带 CHANGELOG 条目；「已上线」以部署 SHA 为证。
  7. 与 Skills 同宽截图对照（1440px、1100px），另附深色与 390px 截图。

### 现在
- **主对象是「Agent 配置」**：职责块（指令、技能、MCP 等）与「运行配置」字段组分开显示；「跑法」不是独立对象，只是 Agent 配置上与职责块分开的运行配置（模型、推理、Runtime 等）。
- **能力页**：skills、MCP、hooks 三类并列为同级条目；来源（本机、仓库、workspace、agent）是过滤项，不是分类。Memory 不再是能力页同级条目（用户 10-28 改判，取代 10-27 的四类并列）。
- **能力三态**：Declared（声明了）、Reachable（路径或连接可达）、Observed（运行中被观察到）；缺失显示 missing / unknown，不推断。
- **Memory 归入 Agent 配置抽屉的 Memory 标签页**：先只显示元数据（名称、来源、更新时间），不显示正文，以后再决定是否放开。数据来源待确认：据 ACM-576 / ACM-577，Atlas 目前看不到任何 bot 的 Memory，Grok Bot 也没有本机可读的 memory 文件。
- **只读且不显示秘密值**：env、header、token 一律不显示。

### 下一步
- **607 拆单**：按上述口径拆成执行单，每张先有一步很短的设计验收清单，再交实现，实现方跑清单并贴截图。[ACM-607]
- **能力证据清单**：skills、MCP、hooks、memory 的只读证据按同一口径展示，与配置管理子视图对接。[ACM-613]

### 以后
- hooks 与 memory 的写入、跨 harness 统一管理，归「跨板块」的统一写入安全设计，本板块只管只读。

### 不做
- 不把 Multica 的产品命名带进 Atlas 界面术语；跨工具通用词汇只落在 Agent 配置页和能力页，不扩散到别的页；不改顶栏。
