# Skills Inventory Changelog

Notes that do not belong in a new inventory field.

## 2026-10-23

- ACM-350 adds `skills-governance/scripts/sync_skills_inventory.py`. The default run is a dry-run summary. `--apply` writes the inventory only when the result still validates. A new install records name, path, source class, and a hash or `baseline_ref`. `review_time` is not given a timestamp. `customization_mode` and `compatibility_constraints` are not changed; a new row uses `unknown` and `[]` because nobody has reviewed it. A content-hash or provider-version change stays on the old baseline and is reported as needs-review; an existing review timestamp is cleared to null. An install whose recorded paths are gone is marked `status: unknown` and kept. Plugin caches are one row per package. Marketplace clones, nested skills, and recorded bundle children are not separate rows. No launchd job, git hook, or autopilot is installed.

## 2026-10-17

- ACM-158 checks `SKILL.md` `capabilities.network`, `capabilities.secrets`, and `capabilities.filesystem` against the SkilLock `behavior` map (`network_urls`, `file_reads`, `file_writes`, `shell_commands`, `allowed_tools`). `skill_guard` records overreach as `capability_overreach` and does not activate, so no changelog line is written. `conflict_markers` from ACM-156 stays a separate gate signal. `capability_contract.py` is the read-only audit. When SkilLock behavior is unmeasured and `capabilities` is absent, the existing `network_behavior` / `secret_access` detectors mark the skill high-risk. High-risk skills with no `review_time` must already be `quarantined` or `policy_exclusion`; both states fail `--promote`. `vaultwarden-secret-migration` declares network, secrets, and filesystem write and is `quarantined` with `review_time` still null. `skills-governance-audit` `baseline_ref` moved with that skill text.
- ACM-202 recalibrates the token footprint gate to a single rule: `token_over_budget` fires when the eager `SKILL.md` exceeds 5,000 static tokens (`EAGER_TOKENS_WARN`), identically at every scope. `size_over_budget` (the 16,384-byte gate), the globally-injected package rule, and the `target_scoped` suggestion are removed; `references_subdirectory` stays the only downgrade suggestion. Referenced docs are still quantified for visibility (`referenced_tokens`, `referenced_bytes`) but never gate the skill, and each referenced `files[]` row now carries `linked` (`true` when SKILL.md links or names the file, `false` when it was only found by scanning `references/`). The skill-level `static_tokens` field is renamed `package_tokens` and `thresholds` is now `{"eager_tokens": 5000}`, so the report is `skills-token-footprint/v2`. `--check` still exits 2 when the gate fails. The only inventory edit is `skills-governance-audit` `baseline_ref`, because that skill text changed.

- ACM-156 adds the `patch` variant for overlay customizations: `customizations/<skill>/local.patch` (a deterministic `git diff --no-index --binary` between upstream baseline and local tree, generated only by `scripts/skill_patch.py create`), a `patch` record field (`sha256` plus a `files` manifest of base hashes) that is mutually exclusive with `ops`, and `skill_patch.py rebase`, which three-way merges the patch onto a new upstream (`git merge-file --diff3`, statuses `replayed`/`absorbed`/`merged`/`conflict`, reasons `content`/`modify_delete`/`binary`). Conflicts write only `<output>/<skill>.conflicts/` with git-style markers and exit 2; a new `conflict_markers` gate signal in `skill_guard` also blocks `diff --gate` and non-force `activate` when a staged file gains `<<<<<<<`/`>>>>>>>` markers. `customization_check.py apply` now refuses patch-style records. No inventory rows changed.
- ACM-155 adds a read-only token footprint report: `python3 skills-governance/scripts/token_footprint.py --format text`. Static tokens are `ceil(utf-8 bytes / 4)` (`bytes_div_4`). Each row quantifies `SKILL.md` and referenced text, including `references/`. `token_over_budget` fires above 2,000 eager static tokens, and also when a globally injected skill's eager file plus referenced docs exceed 2,000. `size_over_budget` fires when `SKILL.md` exceeds 16,384 bytes. Downgrade suggestions are `references_subdirectory` and `target_scoped`. `--check` exits 2 when the gate fails. The command does not modify skills, inventory, or lock files. The only inventory edit is `skills-governance-audit` `baseline_ref`, because that skill text changed. `review_time` stays null.
- ACM-131 adds the non-local skill customization framework: delta records at `customizations/<skill>/customization.json` (`skills-customization/v1`), overlay payloads under `delta/`, `scripts/customization_check.py` with `check` (cross-checks records against `customization_mode`, `baseline_ref`, hashes, path safety) and `apply` (replays overlay ops onto an upstream candidate, exit 2 on conflicts for later three-way merge by ACM-156), `config/skills-customization.schema.json`, and the mode-selection and upgrade workflow in `docs/customization.md`. No inventory rows changed; all current `customization_mode` values stay `none`.
- ACM-173 adds a per-skill activation changelog. `skill_guard.py activate` now appends one JSON line per changed skill to `skills-governance/changelog/<skill>.jsonl` (`skill-governance-changelog/v1`): old/new `SKILL.md` hashes, tree hashes, `metadata.version`, added/removed/modified files, risk signals, summary, `new_ref`, `forced`, `snapshot`, and `staging`. New flags: `--changelog-dir`, `--change-summary` (kept in `summary`, auto text in `auto_summary`), and `--new-ref`. Skills whose tree hash is unchanged and blocked activations write nothing. `drift_report.py` gains `--changelog-dir` (same default) and flags `change_unrecorded` (有变更未记录) when a modified/mismatched skill has no changelog entry whose `new_hash`/`new_ref`/`new_version` matches the observed value; rows carry a `changelog` count and `last_date`, and the summary adds `change_unrecorded`.
- ACM-136 records routing precedence and Stop-and-Ask in `skills-governance/docs/routing-precedence.md`. Specific context wins: target adapter, then project, then canonical local, then runtime plugin, then runtime builtin, then global. The conflict report still does not select which skill runs. `SCOPE_RANK` stays a shadowing breadth rank. Same-name copies with different bytes are not settled by layer rank unless a recorded adapter or customization names the copy. The ego-browser routing note now points at that page and only covers shared sessions, Profiles, and Spaces. Open `conflict_status` values are unchanged.
